## SOLID Principles

### S — Single Responsibility Principle (SRP)
> Класс должен иметь только **одну причину для изменения**.

Одна ответственность → проще поддержка и тестирование.

---

### O — Open/Closed Principle (OCP)
> Программные сущности должны быть **открыты для расширения**, но **закрыты для изменения**.

Новая функциональность добавляется через расширение, а не переписывание существующего кода.

---

### L — Liskov Substitution Principle (LSP)
> Подклассы должны корректно заменять родительские классы.

Если код работает с базовым классом — он должен работать и с его наследниками без ошибок.

---

### I — Interface Segregation Principle (ISP)
> Лучше несколько специализированных интерфейсов, чем один универсальный.

Клиенты не должны зависеть от методов, которые они не используют.

---

### D — Dependency Inversion Principle (DIP)
> Зависимости должны строиться на **абстракциях**, а не на конкретных реализациях.

Высокоуровневые модули не должны зависеть от низкоуровневых.
